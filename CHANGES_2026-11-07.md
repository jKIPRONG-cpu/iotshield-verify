# Changes — 7 November 2026

## Added

- **`tools/crosscheck_model.py`** (`npm run verify:crosscheck`). An independent
  Python re-implementation of the formal net and the property checks, using only
  the standard library. It reproduces the model checker exactly:
  - baseline: 15,876 states and 70,400 transitions
  - hardened: 5,184 states and 19,888 transitions
  - the same verdicts for all eight properties, with and without weak fairness
  - the same violating-state counts

  It also checks the stricter per-device reading of VP-05, which gives the same
  verdicts.
- **`eventb/`**: an Event-B model of the same net, as a Rodin project. It has an
  abstract machine, refinements for the baseline and hardened net that hold for
  any number of devices, and three-device instances for ProB. It also contains
  a plain-text listing, a README with step-by-step instructions, and the scripts
  that checked the model outside Rodin. **It has not yet been run in Rodin**; see
  `eventb/README.md`.

## Corrected

- **VP-06 narrative** (`tools/verify_model.mjs`, `net.ts` comment and the
  regenerated `VERIFICATION_EVIDENCE.md`). The text said the exfiltration
  transition "stays reachable once detection has fired, and legitimate transfers
  are untouched". That is not true of the model. In the hardened net,
  `t-exfil` and `t-resume` never fire, so VP-06 holds because a compromised
  device cannot exfiltrate at all. The text now says so.
- **VP-05 formula and category** (`properties.ts`, regenerated evidence and
  results JSON). The formula text now matches what is checked: if any device is
  in Malware Execution, then some device is eventually isolated. The category
  was "Safety"; it is a liveness property and is now labelled "Liveness".
  **No verdict or count changed.**
- **README**: the summary of results now describes the 8-property results
  (6/8 → 7/8, or 8/8 under weak fairness), and the test counts are updated to
  88 and 81. It previously described the old six-property version with the
  "Analyse Behaviour / Detect Malware concurrently enabled" explanation.

## Not changed, but worth knowing

- Some interface text still gives the old explanation of the VP-05 failure
  ("Detect Malware and Analyse Behaviour were concurrently enabled"):
  `frontend/src/lib/simulation.ts` line 155, `frontend/src/data/mock.ts` around
  line 1231, and the header comment of `frontend/src/pages/PetriNet.tsx`. The
  formal model's actual cause is the deferral arc (see `VERIFICATION_EVIDENCE.md`).
  This text describes the animation layer, not the verified model, but if
  examiners use the demo it should be made consistent.
